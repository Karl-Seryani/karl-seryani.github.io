Google Cloud

Cross-project disk access in Backup and DR

Found an authorization issue in Google Cloud Backup and DR. A user could add another project in the same organization to their own backup policy without permission on that project. The next scheduled backup copied that project’s disk into the user’s backup vault. The user then restored the disk and read its files.

Google triaged the report one day after submission and accepted it.

Multi-agent bug bounty harness

AI security tooling

April 2026 to present

A multi-agent AI system that tests bug bounty programs and tries to disprove each result before it becomes a report.

The system reads a program’s rules, splits the work into tasks, and runs AI agents in parallel. A SQLite database tracks every test and finding. The system produced more than 30 bug bounty reports across 4 programs, including the Google Cloud, Keeper Security, and NASA findings on this page.

Each agent role runs on a different AI model. A finding goes into a report only after it passes two independent reviews and a reproduction on a clean machine.

How it works

Every finding must show real network traffic. A check sends a marked request and fails unless the local proxy recorded that exact request. The recorded requests become the evidence in the report.

Two layers of code keep the agents inside the program rules. One layer blocks any command that could reach the target directly or read a saved password. The other layer checks each request against the allowed hosts and paths. 35 unit tests cover these guards.

Built with Python, SQLite, TypeScript, and Node.js.
