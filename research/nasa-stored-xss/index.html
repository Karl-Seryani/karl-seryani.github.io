Stored XSS leading to account takeover

Stored cross-site scripting in NASA’s GLOBE platform led to an authenticated session for a separate controlled account.

Karl Seryani

Contents

ImpactAffected componentRequired accessRoot causeEvidenceStatusTimeline

Impact

Stored XSS in NASA’s GLOBE platform led to account takeover. Content supplied by one account executed as JavaScript in another user’s browser, and the reported chain produced an authenticated session for that separate account.

The result crossed both the browser’s content boundary and the application’s account boundary: stored user content gained execution privileges, followed by access under another user’s identity.

Affected component

GLOBE’s public visualization platform and the authentication handling involved in the reported chain.

Required access

A GLOBE account able to supply content displayed by the platform. The viewing user encountered the affected content while holding an authenticated GLOBE session.

Root cause

User-supplied content was rendered without safe output handling. Stored data became executable markup when the visualization displayed it.

Weaknesses in the protection and handling of authentication information extended the impact beyond script execution. Together, these failures allowed the chain to reach an authenticated session for the viewing account.

Evidence

The report used two separate controlled accounts. Browser evidence confirmed script execution in the viewing account’s context, and the documented authentication result established a session for that account.

The account takeover result was tied to an actual authenticated session. It was not inferred solely from the presence of stored XSS.

Status

The report was validated as High (P2) and remains unresolved.

Remediation requires safe rendering of stored content and correction of the authentication weaknesses involved in the chain.

Timeline

    Report submitted to NASA’s vulnerability disclosure program.

    Report recorded as unresolved. High (P2).
